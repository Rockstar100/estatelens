# EstateLens

AI property-research workspace grounded in **public information collected from
DarGlobal and Wasalt**, with a source behind every answer.

- **Chat** — ask questions; answers are generated by a free OpenRouter model
  constrained to retrieved passages, with inline numbered citations that resolve
  to real stored pages.
- **Explore** — filter the collected records (source, city, sale/rent, type,
  bedrooms, budget) with options generated from the data.
- **Compare** — up to three records side by side; incomparable prices are flagged.
- **Sources & About** — real coverage numbers, collection dates, retrieval
  method, and the tested model.

> Independent demo. Not affiliated with DarGlobal or Wasalt. All figures shown
> come from stored records, not from the model.

## Architecture

```
React + Vite SPA  ──►  FastAPI (one origin)  ──►  MongoDB (properties/documents/passages/crawl_runs)
                            │
                            └──►  OpenRouter (free model)  ──►  grounded, cited answer (SSE stream)

CLI crawler  ──►  DarGlobal (browser-rendered)          ┐
             └──►  Wasalt   (public JSON API + browser)  ┘  ──►  normalize  ──►  MongoDB + JSONL snapshot
```

- **One image, one origin.** A multi-stage Docker build compiles the SPA and the
  Python runtime serves both `/api/*` and the static bundle.
- **Retrieval is lexical, not semantic**: structured MongoDB filtering over
  normalized property records + a MongoDB text index over source passages. The
  model never sees more than a handful of passages and never receives a URL.
- **Ingestion is CLI-only** — never triggered by a chat request or on startup.

### Repository layout

```

backend/
  app/main.py         FastAPI app (API + static SPA)
  app/api/            chat (SSE), properties, sources, health, readiness

```

## Data collection

Both sites sit behind a JavaScript challenge (Imperva Incapsula on DarGlobal,
Cloudflare on Wasalt). We render public pages with a real browser the way any
visitor would; we do **not** solve CAPTCHAs or defeat a hard block. A page that
still looks like a challenge after rendering is recorded as skipped, not
fabricated.

| Source | Discovery | Extraction |
|---|---|---|
| **DarGlobal** | `sitemap.xml` (served without challenge) → branded development pages, project category pages, informational pages | Browser-rendered HTML → schema.org JSON-LD + the project "key facts" strip + visible text. One `development` record per branded project page. |
| **Wasalt** | Gzipped sitemaps on `cdn.wasalt.sa` (listed in `robots.txt`) → property-detail URLs, category pages, `/s/*` pages. `/search` is never requested (disallowed for generic bots). | Property detail pages use Wasalt's own **unauthenticated public JSON API** (`api.wasalt.com/misc/v3/properties/<id>`, the endpoint the public page itself calls) with `locale: en`. Informational pages (home FAQ, `/s/masterplan`) are browser-rendered. One `listing` record per property. |

Robots, conservative concurrency, a delay between requests, bounded retries, and a
strict domain allow-list are enforced in `app/scrapers/base.py`. Missing fields
are stored as `null` — never `0`. Money is stored as `Decimal128` and serialized
as a string. Ingestion is idempotent: re-running a crawl upserts by stable id and
supersedes changed passages instead of duplicating.

See **[docs/SUBMISSION.md](docs/SUBMISSION.md)** for actual coverage counts,
collection dates, the tested OpenRouter model, test results, and known
limitations.

## Run it locally

Prerequisites: Docker, Node 20+, Python 3.12+.

```bash
cp .env.example .env          # fill OPENROUTER_API_KEY; MONGODB_URI defaults to the compose service

# 1. Backend + MongoDB (compose builds the same image used in production)
docker compose up --build     # → http://localhost:8000

# --- OR run the two parts directly for development ---
# backend
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt
MONGODB_URI=mongodb://localhost:27017 uvicorn app.main:app --reload --port 8000
# frontend (proxies /api to :8000)
cd frontend && npm install && npm run dev     # → http://localhost:5173
```

### Ingestion (CLI only)

```bash
cd backend
pip install -r requirements-ingest.txt
python -m playwright install --with-deps chromium

python -m scripts.cli create-indexes
python -m scripts.cli scrape --source all --limit 60
python -m scripts.cli coverage
python -m scripts.cli validate
python -m scripts.cli export-snapshot --out ../data/snapshots/full-$(date +%Y%m%d).jsonl
python -m scripts.cli import-snapshot ../data/snapshots/full-YYYYMMDD.jsonl
```

### Tests

```bash
cd backend
python -m pytest                       # unit + integration (needs local MongoDB)
python -m pytest -m "not integration"  # unit only
cd ../frontend && npm run build        # typecheck + production build
```

### Docker

```bash
docker build -t estatelens .
docker run --rm -p 8000:8000 \
  -e MONGODB_URI="<atlas-uri>" -e MONGODB_DATABASE=estatelens \
  -e OPENROUTER_API_KEY="<key>" \
  -e OPENROUTER_MODEL="nex-agi/nex-n2.5-mini:free" \
  -e OPENROUTER_FALLBACK_MODEL="nvidia/nemotron-3-super-120b-a12b:free" \
  estatelens
```

## Deployment

`render.yaml` defines a single Docker web service on Render's **free** plan
(`healthCheckPath: /api/health`) with an external **MongoDB Atlas** database.
`MONGODB_URI`, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`,
`OPENROUTER_FALLBACK_MODEL` and `APP_BASE_URL` are set as dashboard environment
variables (`sync: false`) and never committed. Atlas network access must allow
the Render egress range (or `0.0.0.0/0` for the demo — noted as a tradeoff).

The public URL, once deployed and tested, is recorded in
[docs/SUBMISSION.md](docs/SUBMISSION.md).

## Environment variables

| Variable | Purpose |
|---|---|
| `OPENROUTER_API_KEY` | OpenRouter key (free routes only) |
| `OPENROUTER_MODEL` / `OPENROUTER_FALLBACK_MODEL` | tested free model ids |
| `MONGODB_URI` / `MONGODB_DATABASE` | Atlas connection + database name |
| `APP_BASE_URL` | public origin (links, CORS, OpenRouter referer) |
| `PORT` | host-provided listen port (Render sets this) |
| `LOG_LEVEL` | `INFO` by default |

Conversation history is stored **only in the browser** (localStorage) with clear
and delete controls; there is no shared server-side history.
